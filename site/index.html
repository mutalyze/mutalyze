How it works

Three steps. One command.

Run it after your agent finishes. No setup, no accounts, no uploading.

01

Point it at a session

One command after your agent is done. It finds the latest session for your project on its own.

02

It checks the work

ruleguard compares what the agent actually did against the rules you set — reading the real commands and edits, not a summary.

03

You get the receipts

A short report: which rule broke, the exact step it happened, and the command or line that proves it.

Why you can trust it

It doesn't ask an AI to grade an AI.

It shows you the proof

No model decides whether a rule broke. ruleguard points at the exact command or line and the step it happened — so you can open the session and see it for yourself.

Your code never leaves

Everything runs on your machine. Nothing is uploaded, nothing is sent anywhere. The optional team summary shares only anonymised counts — never your code.

Built-in

It catches the dangerous stuff — even with no rules set.

Out of the box, ruleguard flags the things nobody remembers to write down:

!
Deleting your home or system folders

A wipe of the wrong directory — not your project's temp files.

!
Writing a password or key into a file

A real secret landing in a credentials file.

!
Force-pushing over shared history

The kind that overwrites a teammate's work.

!
Running code piped straight off the internet

Downloading a script and running it unchecked.

Honest by default

What it won't do.

A checker is only worth trusting if it's straight about its own edges.

It tells you what it can't check.

Some rules are too fuzzy to verify (“write clean code”). ruleguard lists those plainly instead of pretending it checked them.

It's a rule checker, not a security scanner.

It flags a secret written to a credentials file — not one buried deep in your source. It won't pretend to be more than that.

A quiet report isn't a guarantee.

No rules broken can also mean none of your rules could be checked. ruleguard always shows you which it is.
