§ 01–03
How it works

Compile the rules once.
Execute against the log, deterministically.

Two strictly separated phases. The first may think hard, and only runs once. The second makes zero LLM calls and touches no network — so every finding is a fact you can open the transcript and verify.

01

Compile

Your CLAUDE.md becomes a readable, hand-editable checks.yaml. A rule that can't be verified mechanically is marked unsupported — counted, never guessed at.

# CLAUDE.md → .ruleguard/checks.yaml
- id: CM005 type: command scope: repo
  rule: Use `rg` (not `grep`).
  forbid: [grep]
02

Execute

One streaming pass over the transcript. Turn numbers stay correct across rewinds and subagents; comments and strings are stripped; a Write is checked only when the file was created that session.

Read · t138Edit · t140Bash · t142Grep · t1451 pass · 0 LLM
03

Cite

Every violation names a turn, the line's id, and the literal evidence — you don't trust the verdict, you verify it. The rule's own text stays attached to its finding, ready to re-assert.

turn 142 · CM005
Use `rg`, not `grep`.
Bash → grep -n "DATACENTERS" public/watchover.html
§ 04
Verdicts

Violated, held — or unresolved.

Most tools give two answers. The third is the honest one: when the evidence is ambiguous, ruleguard says so rather than guess.

Violated

The rule broke.

A real, in-scope event that breaks the rule — cited to the turn with the literal command or added line. A violation always rests on evidence you can stand behind.

Held

Ran and passed.

Not silence — an applicable check that stayed satisfied across the session. Held is only ever reported when the check actually ran.

Unresolved

Can't place it — won't claim it.

A command whose directory came from a shell variable can't be put in or out of scope. Reported apart, never counted as a violation and never dropped.

§ 05
What it reads
Three check types

The rules are on disk. The record is on disk.

ruleguard is the part that checks one against the other — reading the tool-call payloads themselves, not just their names.

commandscans Bash inputs — “Use rg, not grep.”
contentscans Write / Edit added lines — “No console.log.”
orderingscans the sequence of tool calls — “Read a file before editing it.”
.ruleguard/checks.yaml
version: 1
- id: CM002
  rule: Never commit directly to `main`.
  type: command
  forbid_pattern: git\s+commit
  when_branch: main

unsupported:
  - Write clean, maintainable code.
    ↳ not mechanically verifiable
§ 06
Built-in

A safety pack that needs no rules file.

Checks nobody bothers to write down but every repo wants — authored precisely, shipped with their verifier, session-scoped. So a first run is never fully silent.

SP001
Never force-push.

--force / -f — but never the safe --force-with-lease.

SP002
Never pipe the network into a shell.

curl … | sh — heredocs and quoted docs don't count.

SP003
Never rm -rf a home or root path.

Recursive deletes of ~, $HOME, or system paths — not your temp dir.

SP004
Never write a key to a credential file.

A secret landing in .env or id_rsa — example files and fixtures excluded.

§ 07
Honest by default

What it won't do.

The instrument is only worth trusting if it's straight about its own edges. These live in the README, not the fine print.

✗
Checkable rules skew trivial.

The rules easy to check mechanically usually aren't the ones that matter. The ones that do get marked unsupported — counted, never faked.

✗
“Secrets to disk” is destination-scoped.

It catches a key written to .env or id_rsa — not one hard-coded into config.ts. It is not a full secret scanner and doesn't pretend to be.

✗
A quiet run is not a clean bill of health.

Zero findings can mean the agent complied — or that your rules compiled to unsupported. Read the compiled / unsupported counts, not just the violation number.

§ 08
Local by default

Your code never leaves your machine.

A default run computes everything locally and prints a report. It transmits nothing and phones nothing home.

The optional team payload — ruleguard check --signals — sends only hashes, categories, and counts. Never a command, a path, or a rule. A leak-guard re-checks the payload and refuses if any raw content slipped in. --signals is a flag, never a default.
